```text
┌─ MainActivity ─────────────────────────────┐
│  SubsurfaceTheme (روشن/تیره، تابع سیستم)   │

│    ├─ پیش‌نویس منطقه (بقادار در چرخش/مرگ) │

               │ StateFlow

│    └─ MapLibreMapView (AndroidView)        │

│         └─ GeoJSON خط/رأس‌های پیش‌نویس     │
```

## ۵. جزئیات مهم‌ترین رفع‌ها

### C-1 — بقای پیش‌نویس (مهم‌ترین باگ)

**علت:** `val vertices = remember { mutableStateListOf<GeoPoint>() }` فقط در حافظه
کامپوزیشن زنده است؛ با چرخش صفحه، کل پیش‌نویس کاربر پاک می‌شد.

**راه‌حل:** state به `MapViewModel` منتقل شد و در `SavedStateHandle` آینه می‌شود.
چون `Bundle` نمی‌تواند `GeoPoint` را مستقیم نگه دارد، انکدینگ متنی بدون‌اتلاف
`"lat,lng"` (راندتریپ دقیق `Double.toString`) به‌کار رفت تا نیازی به پلاگین
`parcelize` نباشد. داده خراب به‌جای کرش نادیده گرفته می‌شود (تست‌شده).

### H-1 — حذف کرش `require`

`require(lookbackDays in ...)` در مسیر UI یعنی کرش با ورودی بد. حالا همه ورودی‌ها
(رأس‌ها، هندسه، بازه تاریخ، سقف ابر) **قبل** از درخواست اعتبارسنجی و به‌صورت
`Error state` قابل نمایش برمی‌گردند؛ API هم هرگز با ورودی ناقص صدا زده نمی‌شود.

### H-3 — `HttpJsonClient` مشترک

ساخت اتصال، تایم‌اوت‌ها، `User-Agent` نسخه‌دار (`BuildConfig.VERSION_NAME`)، ساخت
رینگ بسته GeoJSON و پارس خطای FastAPI (`detail` رشته‌ای یا لیست ولیدیشن) یک‌جا
متمرکز شد؛ هر دو کلاینت حالا فقط قرارداد request/response خودشان را دارند.

### M-5 — تشخیص بیلد بدون اندپوینت

اگر هاست URL به `.invalid` ختم شود (پیش‌فرض عمدی ریلیز)، به‌جای `UnknownHostException`
گنگ، پیام «بیلد بدون اندپوینت؛ با `-PAPI_BASE_URL` ری‌بیلد کنید» نمایش داده می‌شود.
